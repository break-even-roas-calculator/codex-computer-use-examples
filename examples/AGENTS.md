# Choosing a surface for computer and browser work

When a task involves another application, pick the surface in this order.

1. Structured tools first. If a plugin or MCP server covers the action
   (Slack threads, GitHub actions, calendar, files), use it. Its output is
   easier to inspect and faster than driving a user interface.

2. @Chrome for browser work that needs several tabs or an existing login.
   Use the Chrome extension when the task lives in a website and the session
   already has the right account signed in.

3. @Computer only when nothing structured exists: a native desktop app, an
   iOS simulator or iPhone Mirroring, System Settings, a data source with no
   plugin or API, a workflow that moves between several apps, or a single
   missing action inside an otherwise useful integration.

## Rules for @Computer

- Operate one app or one flow per task. Do not open unrelated apps.
- State which app you are about to use before using it.
- Stop and ask before any change involving payment, account or subscription
  settings, credentials, privacy settings or system security.
- After finishing, take a screenshot of the final state and summarize the
  exact actions taken.

## Apps approved for this repository

- Xcode and the iOS simulator (for reproducing UI bugs)
- iPhone Mirroring (for on-device checks)

Any other app requires a human to approve it in Settings first.
